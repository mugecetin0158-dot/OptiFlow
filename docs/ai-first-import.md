# AI-first Smart Import (development)

Smart Import parses CSV and XLSX worksheets in the browser. After explicit consent it sends a bounded metadata profile (headers, inferred types, row counts, and up to three short representative values per column) to the private FastAPI `/import/interpret` endpoint. Likely employee identifiers, names, payroll fields, and other sensitive sample values are redacted before transmission. The server calls Gemini with `GEMINI_API_KEY` and returns schema-checked mappings, model semantics, and targeted missing-information questions. The browser never receives the key.

Copy `.env.example` to an untracked `.env`, set `GEMINI_API_KEY`, then start the private server with `PYTHONPATH=. .venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000`. Set `NEXT_PUBLIC_API_URL=http://127.0.0.1:8000` before `npm run dev`. The endpoint limits requests to ten files and 16 KB of metadata, requests destination-constrained structured JSON from Gemini's `v1beta` `generateContent` endpoint (default model `gemini-2.5-flash`), uses configurable timeouts/retries, and handles rate limits explicitly. The provider schema is compact and inlined to avoid structured-output complexity limits; strict Pydantic validation remains authoritative for all fields, values, and collection limits after generation. The selected destination determines the allowed dataset types in both the interpretation instructions and the provider response schema. When a spreadsheet does not match that destination, the AI must leave it unclassified and return an actionable destination note; it is never silently relabeled. A response that combines a dataset classification with a destination-mismatch note is rejected as contradictory. Failures returned as HTTP 502 are logged with the safe model identifier, application status, upstream status when available, and a normalized category; provider response bodies and import data are not logged. Provider charges depend on the configured Gemini model; no call is made before consent. No provider SDK package is required.

The public static Sites deployment cannot host this private API or store its key. Production AI import requires hosting the existing FastAPI service privately, setting the public API origin in `NEXT_PUBLIC_API_URL` at build time, and configuring a specific production CORS origin. Until then, the AI-first import stops with a clear configuration error and can be retried; the currently deployed site has not been changed.

Gemini's checked dataset and column mappings are applied to the locally parsed rows by the deterministic Scheduling transformer. Confident records populate the editable, source-traceable preview immediately, even when separate model-level questions still need answers. Uncertain mappings remain in review; missing datasets and invalid values are reported by deterministic validation and are never filled with invented values. Rebuilding after preview edits requires explicit confirmation.

The protected `GET /diagnostics/gemini` endpoint lists models that advertise `generateContent`; this does not verify that generation succeeds for the configured model and API key. To compare generation across `v1beta` and `v1`, call `/diagnostics/gemini?probe=true` with the diagnostic bearer token. Both requests use the same server-side API key and normalized configured model name as discovery, and send only a fixed synthetic prompt. The `generation_probe` response contains per-version application/provider HTTP statuses and normalized error categories; it never includes generated text or raw provider errors. A provider `401`/`403` indicates an API-key or project authorization problem. A `404` indicates a generation model/method/endpoint failure, though Google may mask inaccessible model access as not found. The two requests may incur small model charges.

To compare structured-output support, call `/diagnostics/gemini?structured_output_probe=true` with the same diagnostic bearer token. It sends a minimal JSON schema and then the actual Smart Import schema, both with synthetic-only prompt text, the configured model, `v1beta`, and identical generation settings and server credentials. Set `target=allocation` to test its destination-specific schema; Scheduling is the default. The response includes only provider HTTP statuses, normalized categories, and a comparison result. Categories distinguish schema complexity, unsupported schema properties, other schema rejection, request-parameter errors, and transport/provider failures. Raw provider responses and generated content are never returned or logged. These two calls may incur small model charges.

AI suggestions never become optimizer inputs directly. Scheduling still uses the existing transformation, record validation, rules, and save gates. Unresolved fields and proposed substantive corrections require review. Resource Allocation still validates the transformed catalogs before they replace the workspace. A saved source profile cannot bypass validation. GLPK and independent result verification are unchanged.

Current limitations: the AI endpoint processes only metadata, so it cannot infer facts absent from source columns; unusual row-level semantics require human verification. Import sessions and completed models use a replaceable in-memory development repository and are lost on restart. A persistent repository, authentication, tenant isolation, and a distributed rate limiter are required before commercial deployment. The static frontend needs a private API host before AI-first import can work for public visitors. Live Gemini connectivity has not been tested without a user-supplied credential.
